Development Guide

Set up a local development environment that mirrors production without exposing Paytm credentials or token flows to the browser surface.

Security boundary

Users interact with your site and your backend only. Paytm login, token exchange, and session inspection are private operator functions exposed through CLI scripts, not HTTP routes.

Public

API surface

  • — REST endpoints for market data
  • — WebSocket gateway at /ws/market
  • — Readiness checks
Private

Operator scripts

  • — Paytm login URL generation
  • — Token exchange
  • — Session inspection
  • — Provider data verification

Environment variables

Your Paytm API key, secret, and other credentials should be set in a .env file at services/api/.env. See .env.example for the required keys.

Local workflow

Start services in dependency order. Redis and Postgres must be running before the API, and the catalog should be synced before market commands work. Each step runs in a separate terminal unless backgrounded.

1

Start Redis and Postgres

Spin up the Redis and Postgres containers via Docker Compose:

docker compose -f deploy/docker-compose.yml up redis postgres

Redis acts as the backplane: pub/sub message bus, quote cache, subscription lease storage, and candle cache. Postgres backs the Drizzle schema and migration state. They must be reachable on ports 6379 and 5432.

2

Apply database migrations

Bring the local Postgres schema up to date:

bun run db:migrate

Runs the checked-in Drizzle migrations so the API starts against the expected schema.

3

Sync the instrument catalog

Refresh the local Paytm security-master snapshot:

bun run worker:catalog

Fetches the full instrument list from Paytm and writes data/instruments.snapshot.json. Run this once on first setup and periodically to keep the catalog current.

4

Start the API server

Launch the HTTP and WebSocket server:

bun run dev

Starts on port 3000 by default. Verify with curl http://localhost:3000/ready. Hot-reload is enabled for development.

5

Start the ingest worker

Run the Paytm upstream stream consumer in another terminal:

bun run worker:ingest

This is a singleton — it owns the upstream WebSocket connection to Paytm, subscribes to requested symbols, and publishes quotes to Redis pub/sub. Only one instance should run.

Paytm login flow

The login flow is entirely CLI-based. No browser endpoint is involved. You need valid Paytm SmartConnect API credentials configured in your .env.

1. Generate a login URL

bun run paytm:login-url

Prints a Paytm SmartConnect login URL. Open this URL in a browser where your Paytm account is logged in. Paytm will redirect to your configured callback URL with a requestToken query parameter.

This operator command only needs the Paytm credentials and local data/ files. Redis and Postgres do not need to be running.

2. Exchange the request token

After Paytm redirects, extract the requestToken value from the redirect URL and pass it to the exchange script: 

bun run paytm:exchange-token -- <requestToken>

Exchanges the request token for a persistent access token. The session is saved to data/paytm-session.json. This file must persist across restarts so the ingest worker can re-establish the upstream connection.

3. Verify the session

bun run paytm:session

Inspects the stored session state: access token validity, expiry timestamp, and associated metadata. Run this to confirm login succeeded before starting the ingest worker.

Provider data verification

Before wiring the frontend, verify that the full pipeline works end-to-end — from Paytm through the ingest worker to the API.

Live market data check

bun run verify:paytm -- RELIANCE

Uses the stored Paytm session, resolves the instrument from the local catalog, and pulls a live market data response directly from Paytm's API. Prints the raw response for inspection. If this works, the ingest worker will also function correctly.

API smoke test

Run these curl commands back-to-back:

curl http://localhost:3000/ready
curl "http://localhost:3000/v1/market/instruments/search?q=RELIANCE&limit=1"
curl "http://localhost:3000/v1/market/quotes?ids=RELIANCE&mode=QUOTE"

Expected results:

  • — /ready returns 200 with "ready": true
  • — /search returns 200 with matching instruments
  • — /quotes returns 200 with quote data (or cached data)

Testing

The test suite covers market data parsing, catalog lookup, WebSocket fanout, the readiness contract, and confirms auth endpoints are not exposed. Run it after any code change. 

bun test tests

Market parsing

Validates quote and trade parsing from Paytm's wire format. Covers malformed payloads.

Instrument resolution

Tests catalog lookup by symbol, security ID, and instrument key. Edge cases for missing entries.

WebSocket protocol

Subscribe and quote event flow. Confirms fanout reaches connected clients.

Readiness & auth

/ready returns 503 when deps missing. Auth routes return 404.

Troubleshooting

Redis connection refused

Ensure Docker is running and Redis is started:

docker compose -f deploy/docker-compose.yml up redis postgres

Check if Redis is listening on port 6379.

Paytm session expired

Re-run the login flow:

bun run paytm:login-url
# open URL, copy requestToken
bun run paytm:exchange-token -- <requestToken>
bun run paytm:session
DB schema is out of date

Apply the checked-in Drizzle migrations:

bun run db:migrate
Catalog not found

The catalog snapshot file is missing. Run:

bun run worker:catalog

This writes data/instruments.snapshot.json.

WebSocket connects but no quotes arrive

Verify the ingest worker is running and the Paytm session is valid. Check worker logs for subscription errors. Run the verification script:

bun run verify:paytm -- RELIANCE
